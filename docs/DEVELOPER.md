# Разработка карты больниц

## Текущая архитектура

Проект собирается Vite как две самостоятельные страницы, `index.html` и `developer.html`. Сборка остаётся полностью статической. PowerShell запускает прежний loopback-сервер .NET и раздаёт `hospital-map/`; Node.js нужен только разработчику.

React управляет разметкой, состояниями элементов и событиями обеих страниц. Общие элементы находятся в `src/components/ui/` и получены официальным CLI shadcn/ui. Просмотрщик использует отдельные сервисы чтения снимка, хранилища и расчётов.

`DeveloperWorkspace` передаёт контроллеру `DeveloperTablesHandle`: `update(source)` публикует типизированный снимок, `open(request)` открывает нужный набор с организацией и поиском из карточки. `src/developer/table-data.ts` преобразует снимок в строки, выполняет поиск, пагинацию и CSV без DOM и глобальных объектов. Значения показателей и выбор координат по-прежнему получает контроллер из прежнего ядра. Изменяемые карты геокодирования и значения настроек копируются на границе; новые результаты адресного поиска передаются сгруппированно с задержкой до 100 мс, настройки и восстановление — сразу.

В инструментах разработчика `createDeveloperUI()` из `src/runtime/developer-ui-store.js` связывает расчётные контроллеры и React без поиска элементов страницы. Контроллер публикует значения полей, снимки данных и команды. `src/developer/DeveloperUI.tsx` подписывается через `useSyncExternalStore`, передаёт состояния компонентам shadcn/ui и обрабатывает события. Контроллер не записывает HTML и не меняет реальные DOM-элементы оболочки. Диалоги, фокус, ошибки, прогресс и навигация отображаются React. Экземпляр карты и временная ссылка для скачивания остаются в специализированных модулях.

`src/engine/` содержит JavaScript-алгоритмы геометрии, метрик, маршрутов, резервных копий и кэша. TypeScript описывает данные и связи интерфейса и сервисов. При замене компонентов формулы и форматы хранения не меняются.

Обёртка карты управляет созданием и уничтожением экземпляра Яндекс Карт. При размонтировании должны останавливаться Worker и запросы, сниматься обработчики и отменяться отложенные обновления. Повторный запуск эффектов React StrictMode не должен создавать вторую карту или повторно записывать данные. Яндекс API загружается извне; его доступность не подтверждается одной успешной сборкой.

## Команды

Из корня проекта, Node.js 22.12+:

```powershell
npm ci
npm run dev
npm run typecheck
npm test
npm run build
npm run package
```

`npm ci` использует зафиксированный `package-lock.json`. `npm run build` проверяет типы, собирает Worker, запускает production-сборку Vite и обновляет `package-manifest.json`. Архив создаётся в `dist/`; перед упаковкой все перечисленные файлы сверяются по SHA-256. В архив не попадают `node_modules`, исходники интерфейса, рабочие графы и загруженные файлы OSRM.

Worker собираются из актуальных исходников при каждой сборке. В режиме `npm run dev` Vite следит за `src/engine/` и `src/workers/`, пересобирает Worker и перезагружает страницу при изменениях. Не редактируйте выходные файлы Worker вручную. Ссылка на Worker разрешается относительно статической поставки, без обращения к серверу Vite.

Геометрические библиотеки берутся из `src/engine/vendor/` и входят в bundle интерфейса и Worker. Лицензии и NOTICE копируются в поставку из `public/vendor/`. Какие файлы создаёт сборка, описано в [REFACTORING.md](REFACTORING.md).

`START.cmd` запускает `scripts/Start-Map.ps1`. Для проверки без автоматического открытия браузера:

```powershell
./START.cmd -NoBrowser
# либо
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./scripts/Start-Map.ps1 -NoBrowser
```

Сервер начинает с порта 8765 и проверяет ещё 31 порт. Он переиспользует только сервер с той же идентичностью папки и сборки. Адрес страницы сохраняется: `http://localhost:8765/` и `http://localhost:8765/developer.html`. При выборе другого порта браузерное хранилище будет другим, как и в прежней реализации.

## Контракты совместимости

Не меняйте следующие контракты без отдельного явного плана переноса данных:

- IndexedDB разработчика: `hospital-map-local-data`, версия 1, хранилище `results`, ключ `key`.
- IndexedDB просмотрщика: `hospital-map-viewer-routes-v1-` плюс первые 16 символов контрольной суммы снимка, версия 1, хранилище `routes`, ключ `key`.
- localStorage: `hospital-map-settings`, `hospital-map-keys`, `hospital-map-accessibility`, `hospital-map-viewer-settings-v1`.
- Формат резервной копии, её контрольная сумма и способы объединения записей. API-ключи в резервную копию не входят.
- Ключ маршрутного кэша включает способ передвижения, сервис, исходную точку, назначение и организацию. Ошибка сети не равна отсутствию пути.
- Координаты Яндекс Карт и маршрутизатора в состоянии приложения идут как `[широта, долгота]`; кольца GeoJSON — `[долгота, широта]`. Преобразование выполняется на границе карты/GeoJSON.

Просмотрщик проверяет SHA-256 распакованного `viewer-data.js` до использования. Фильтрация отображения не изменяет исходный снимок и `data/full-project.json`. Для намеренной публикации завершённого перерасчёта служит `scripts/publish-routes.mjs`: он проверяет полную копию и receipt, сохраняет прежние файлы и согласованно обновляет `sourceChecksum` и gzip-снимок. После публикации обновите ожидаемые SHA/контрольные количества регрессионных тестов и выполните сборку. Пользовательская карта не импортирует полную резервную копию автоматически и не требует заполненного IndexedDB при первом запуске.

Расчёт маршрутов сохраняет результаты порциями и позволяет остановку и продолжение. Уже сохранённые ответы не запрашиваются повторно. При остановке необходимо дождаться завершения текущей записи. Оценённые по соседям времена хранятся только в производном отображении: они не записываются как `found` и не становятся донорами для следующих оценок.

Сохранены два отдельных профиля OSRM: автомобильный `http://localhost:5000/route/v1/driving` и пеший `http://localhost:5001/route/v1/foot`. Замена слова `driving` на `foot` не заменяет профиль графа; каждый сервер должен быть подготовлен со своим профилем.

На обеих страницах общий `HospitalAccessibility.displayBand` использует `visibleTime` для пешего часового окна: конечное неотрицательное время не больше 3 600 секунд сохраняет свой временной цвет, остальные ячейки получают серый цвет. Все полигоны сетки остаются видимыми; линии пешего маршрута дольше часа не рисуются. `completeTimes`, счётчики, резервные копии и маршрутные записи не фильтруются. Оценки сохраняют `≈` и источник.

CLI массового расчёта использует `local-routing/engine.cjs`, автоматически собранный из тех же движков при `npm test` и `npm run build`. Поэтому CLI работает и в распакованном ZIP при отдельно установленном Node.js, без npm и исходников `src/`. Для обычного просмотра и `START.cmd` Node.js по-прежнему не требуется. Свежий автомобильный запуск: `node local-routing/calculate-routes.cjs --input data/full-project.json --output .tmp/recalculation/auto-fresh.json --mode auto --fresh`. Для продолжения повторите команду **без `--fresh`**. Новый output исключает старые ответы выбранного режима; повторный запуск с тем же output продолжает только его собственную проверенную контрольную точку. Смена графа, исходной копии или параметров требует другого output. Подробности — в `local-routing/README.md`.

В просмотрщике прикрепление на 1 000 жителей окрашивается по фиксированным порогам: меньше 700, от 700 до 1 000 включительно, больше 1 000; отсутствующее значение серое. В разработчике остаются терцили. Алгоритм заполнения пропусков — по соседним измеренным ячейкам той же больницы; принадлежность ячейки при заполнении не меняется.

## Контроль результата

Перед выпуском запускайте проверки типов, тесты, сборку и упаковку. Через штатный сервер проверьте обе страницы, таблицы, карточки, фильтры, три режима карты, оба режима передвижения и изменение сетки. В отдельном профиле браузера проверьте импорт `data/full-project.json`, экспорт, повторную загрузку, остановку и продолжение расчёта. Для проверки прежнего браузерного хранилища открывайте тот же протокол, имя хоста и порт, которые использовали до миграции.

Автоматическая проверка статической поставки в Windows:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./scripts/Verify-Static.ps1
```

Она вызывает именно `START.cmd` с PATH, в котором доступны только Windows-инструменты, сверяет все HTTP-ресурсы с манифестом, проверяет повторный запуск и выбор следующего порта. По умолчанию нужны свободные порты 19765 и 19766; сценарий не останавливает пользовательские серверы. Параметр `-PackageRoot` позволяет проверить отдельно распакованный архив, `-Port` — выбрать другие тестовые порты.

Регрессионные ориентиры исходного снимка: 38 больниц; 1 942 ячейки сетки 5 км; 3 884 ответа OSRM. Автомобильные времена: 1 258 найденных и 684 оценённых. Пешие: 1 733 и 209. Сам исходный файл полной копии имеет SHA-256 `99e629c34076ff6de23bcadf740219d22615bb56299c83b277d20b6bcc1b10cf`; исходный `viewer-data.js` — `af969330fbae410ba119d09e8412861e16d0a77b0d8affdbeabe7f9ec35338a1`.

Если Яндекс или локальные OSRM недоступны, отдельно фиксируйте локальные проверки и непроверенные внешние сценарии. Не считайте тест с подменённым API подтверждением работы реального сетевого сервиса.

Общая тема, CSS-токены и проверка shadcn/ui описаны в [SHADCN.md](SHADCN.md). Монохромные состояния относятся к оболочке; цвета геометрических слоёв, легенды и подложка Яндекса сохраняют смысл данных.
