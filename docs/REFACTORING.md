# Таблицы и загрузка SDK

Это запись этапа после первичного переноса на React, до shadcn/ui. Текущее устройство интерфейса описано в [DEVELOPER.md](DEVELOPER.md) и [SHADCN.md](SHADCN.md).

## Изменения этапа

Шесть таблиц разработчика перенесены в React вместе с поиском, фильтрами, пагинацией и CSV. `DeveloperTablesHandle` передаёт снимок данных и команду открытия набора из карточки. `src/developer/table-data.ts` готовит строки и форматирование без DOM; показатели по-прежнему вычисляет ядро. Изменяемые коллекции копируются на границе, близкие обновления геокодирования объединяются с задержкой до 100 мс.

Загрузчик Яндекса исправлен: ограничение в 20 секунд действует до фактического `api.ready`, а не только до загрузки скрипта. Поздний callback не завершает другую попытку подключения; после ошибки разрешена повторная загрузка.

Удалены неиспользуемые JS-копии Clipper и D3 Delaunay из `public/vendor/`. Интерфейс и Worker используют `src/engine/vendor/`; лицензии и уведомления авторов сохранены. Очереди маршрутов двух страниц остаются отдельными: разработчик сохраняет линии маршрутов, просмотрщик их исключает.

## Историческая проверка — 27 октября 2026

Результаты ниже относятся к этому этапу и не заменяют проверку текущего интерфейса:

- Прошли TypeScript, 27 тестов, production-сборка и упаковка. Исходные контрольные суммы, формулы, ключи маршрутов, схемы IndexedDB, резервные копии и Worker сохранили прежние результаты.
- `Verify-Static.ps1` проверил `START.cmd` без Node/npm, соответствие HTTP-ресурсов манифесту, переиспользование сервера и переход на следующий порт. На тот момент поставка содержала 21 статический ресурс.
- Через Vite проверены поиск, выбор организации, страницы по 75 строк и восстановление фильтра после смены набора. Через интерфейс скачан CSV с BOM, заголовком и шестью найденными повторными строками.
- Через штатный сервер проверены шесть таблиц и их количества строк. [Исторический снимок таблиц](screenshots/developer-tables.png) показывает оформление до shadcn/ui.
- Пользовательская страница загрузила снимок и реальный SDK Яндекса; проверялись три режима, оба способа передвижения, карточка, таблица 38 больниц и выбор сетки. В консоли не было ошибок.
- Локальные OSRM не ответили. Новые сетевые маршруты и остановка/продолжение с ними не подтверждены. Полный импорт/экспорт через UI на этом этапе повторно не проверялся; форматы и восстановление проверялись автоматическими тестами.

Проверки проходили в отдельном браузере автоматизации на тестовых портах. Личный профиль пользователя не менялся.

## Исходники и результат сборки

Редактируйте интерфейс в `src/`, входные страницы в `frontend/`, статические данные и лицензии в `public/`. Имена ресурсов с хешами не закреплены: актуальный состав поставки перечислен в `package-manifest.json`.

- `hospital-map/` целиком создаётся через `npm run build` и обязателен для запуска `START.cmd`.
- `public/workers/accessibility.js` и `public/workers/zones.js` создаются командами тестов, разработки и сборки.
- `dist/tula-hospital-map-v*.zip` создаётся через `npm run package`.
- `src/engine/vendor/`, лицензии, `public/region.js`, исходные данные и `data/full-project.json` не являются временными файлами.

Не правьте отдельные собранные bundle или Worker: после изменения исходников пересоберите поставку и манифест. Отсутствующие старые пути скриптов в `hospital-map/` заменены ресурсами сборки; восстанавливать их из прежней версии приложения не нужно.
