По уточнению пользователя все квадраты пешей сетки остаются на карте. Общий `displayBand` обеих страниц сохраняет временной цвет только для конечного неотрицательного времени ≤3 600 секунд. Более долгие пути и ячейки без времени показаны серым с легендой «Вне часа / нет данных». Значения не округляются и не ограничиваются искусственно; линии дольше часа не рисуются. Исходные ответы, оценки, счётчики и экспорт не меняются. В подсказках оценок показаны `≈` и источник. Автомобильный слой не ограничен часом.

## Проверка маршрутов и причина ограничения

В исходном снимке 38 больниц, 1 942 ячейки 5 км, 3 884 ответа OSRM. Все ключи маршрутов согласуются с организацией, способом движения, сервисом, origin и destination. Все origin находятся внутри своих геометрий. Все hospital destination совпадают с координатами `public/data.js`; это проверка внутренней согласованности, а не обследование фактических въездов больниц.

В состоянии используются `[широта, долгота]`, в GeoJSON и URL OSRM — `[долгота, широта]`. Преобразование выполнено на границе сервиса. Ошибки порядка координат не найдены. При этом обнаружена вероятная ошибка сопоставления удалённых подразделений с головными учреждениями:

| Запись | В исходном шаблоне | Отдельная опубликованная площадка |
|---|---|---|
| `arsenyevo` (82 ячейки) | Одоев, Дачная, 2 | Арсеньево, Халтурина, 13 |
| `plekhаnovo` (21 ячейка) | Рассвет, 38 | Плеханово, Заводская, 1А |

Все четыре площадки отдельно перечислены в [официальном списке ТФОМС](https://omstula.ru/news/news/6318/). Для Плеханова адрес также указан в [муниципальном проекте](https://www.npatula-city.ru/upload/iblock/d3f/%D0%A2%D0%BE%D0%BC%202.%20%D0%9C%D0%B0%D1%82%D0%B5%D1%80%D0%B8%D0%B0%D0%BB%D1%8B%20%D0%BF%D0%BE%20%D0%BE%D0%B1%D0%BE%D1%81%D0%BD%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D1%8E%20%D0%9F%D0%9F_.pdf), стр. 7, со ссылкой на письмо Минздрава. Это исторические публикации 2020–2021 годов; действующие в 2026 году адреса и точные въезды независимо не подтверждены. Номер Арсеньевского филиала в источниках также расходится с проектом. До подтверждения точных координат нельзя считать все конечные точки физически проверенными; они сохранены, чтобы не подставить произвольные точки и не рассогласовать зоны, кэш и снимок. Перед новым реальным расчётом нужно исправить эти две привязки, затем заново построить покрытие.

Автомобильные ответы: 1 258 `found`, 669 `NoSegment`, 15 `NoRoute`. Среди найденных маршрутов привязка origin к дороге достигает 998,28 м; у 427 она больше 500 м. Максимальная привязка больницы — 162,63 м у ТОКБ. Время OSRM относится к точкам на сети; подход от исходной точки до привязки в него не добавляется. Это объясняет часть различий между картой и ожидаемой поездкой от конкретного дома. `NoSegment` при радиусе 1 км и отсутствие связного пути не доказывают ошибку расчёта.

По сохранённым линиям медианная средняя автомобильная скорость около 45,61 км/ч, пешая — 4,99 км/ч. Это косвенно согласуется с разными профилями. [OSRM определяет профиль при подготовке графа](https://project-osrm.org/docs/v5.24.0/api/), а не заменой слова в URL. Текущий автомобильный граф подтвердить невозможно: серверы `localhost:5000/5001` недоступны. Штатный Docker Desktop удалось запустить, но в нём нет контейнеров, образов и томов OSRM. Исторический дистрибутив `Ubuntu-24.04` отсутствует. В существующем `Ubuntu` проверен штатный запуск `Start-OSRM-WSL.ps1 -Distribution Ubuntu -ExistingOnly`; он сообщает об отсутствии подготовленных PBF, `region.source`, digest образа и обоих графов. Крупная установка нового окружения не выполнялась.

Подтверждённая программная проблема: прежний CLI после React-миграции ссылался на удалённые старые файлы `hospital-map/accessibility.js` и другие модули. Теперь он использует автоматически собранный самостоятельный `local-routing/engine.cjs`. Ещё одна причина ненастоящего «повторного расчёта» — совместимый маршрутный кэш содержит URL, но не версию графа. Обычная кнопка продолжает сохранённые ответы. Новый CLI со свежим output исключает старые автомобильные записи из входной копии и продолжает только собственные новые контрольные точки с совпадающими параметрами и идентичностью графа.

## Запуск и оставшаяся работа

Рабочая версия: запустите `START.cmd` в корне проекта. Демонстрация: полностью распакуйте `dist/tula-hospital-map-development-demo-2026-10-27.zip`, запустите его корневой `START.cmd`. Требуются штатные Windows PowerShell/.NET; Node/npm/Vite для просмотра не нужны. Основной адрес — `http://localhost:8765/`, инструменты — `http://localhost:8765/developer.html`. При занятом порте сохраняются прежний выбор следующего порта и правила повторного запуска. Для прежних данных браузера важны те же протокол, hostname и порт.

Для завершения автомобильного перерасчёта восстановите PBF и подготовленные графы car/foot по `local-routing/README.md`, подтвердите профиль и образ, запустите службы. Затем выполните свежий автомобильный CLI расчёт в отдельный output с `--mode auto --fresh`; для остановки используйте Ctrl+C, для продолжения — ту же команду без `--fresh`. Завершённую копию и receipt опубликуйте в рабочем проекте через `scripts/publish-routes.mjs`, обновите ожидаемые SHA и количества тестов, выполните `npm test`, `npm run build` и упаковку. Publisher создаёт резервные копии прежних файлов перед заменой и отказывается публиковать незавершённый результат. Пешие ответы при этом сохраняются.

Пример публикации в исходном проекте после полного реального расчёта:

```powershell
node scripts/publish-routes.mjs --input data/full-project-auto-new.json --receipt data/full-project-auto-new.receipt.json
# Обновите ожидаемые SHA/количества tests/regression.test.mjs по отчёту publisher.
npm test
npm run build
node scripts/package.mjs --name tula-hospital-map-development-demo-2026-10-27.zip
```

Publisher предназначен для проекта с `public/` и последующей сборкой, в демонстрационный ZIP он не включён. Самостоятельный CLI расчёта в ZIP включён. После изменения координат удалённых подразделений нужно перестроить полное покрытие и пешие результаты: узкая авто-публикация намеренно запрещает менять геометрию и пешие записи под видом обновления только машины.
