# Карта больниц Тульской области

Статическое приложение с двумя страницами: карта для пользователя и инструменты разработчика. Обе страницы используют React, TypeScript и shadcn/ui; сборку выполняет Vite. Геометрия, расчёты и хранение данных находятся в отдельных модулях.

## Запуск готовой поставки

1. Полностью распакуйте архив `tula-hospital-map-v*.zip` в папку Windows 10 или 11.
2. Запустите **START.cmd** в корне папки.
3. Оставьте окно сервера открытым на время работы. Для остановки нажмите Ctrl+C или закройте окно.

Пользовательская страница открывается по адресу `http://localhost:8765/`, инструменты разработчика — `http://localhost:8765/developer.html` с прежним кодом доступа. Если порт занят, скрипт проверяет следующие 31 порт; повторный запуск той же сборки в той же папке переиспользует её сервер. Скрипт проверяет комплектность и SHA-256 статических ресурсов по `package-manifest.json`.

Для готовой поставки достаточно штатных Windows PowerShell 5.1 и .NET Framework. Node.js, npm, Python и Vite для её использования не нужны. Файлы уже собраны в `hospital-map/`. Подложка Яндекс Карт требует интернета и действующего ключа; просмотр готовых результатов не обращается к OSRM. Для новых расчётов нужны локальные серверы OSRM на портах 5000 и 5001. Подготовка описана в [local-routing/README.md](local-routing/README.md).

Не меняйте `localhost` на `127.0.0.1`, протокол или привычный порт при восстановлении старых данных браузера: IndexedDB и localStorage привязаны к полному адресу сайта. На другом адресе перенесите данные через резервную копию.

## Разработка

Нужны Node.js 22.12+ и npm. Из корня проекта:

```powershell
npm ci
npm run dev
```

Vite выводит адрес сервера разработки. Обе страницы доступны и там; браузерные данные этого адреса независимы от готовой поставки на порту 8765. Для проверки со старыми данными используйте production-сборку через `START.cmd` на прежнем адресе.

```powershell
npm run typecheck
npm test
npm run build
npm run package
```

Сборка проверяет TypeScript, заново собирает Worker из актуальных модулей, создаёт статические страницы в `hospital-map/` и обновляет контрольные суммы. Упаковка проверяет файлы по манифесту и создаёт `dist/tula-hospital-map-v*.zip`. В архив входят готовые ресурсы, штатный сервер, документация, полная резервная копия и сценарии OSRM. Зависимости Node.js и исходники интерфейса для запуска архива не нужны.

## Данные и устройство проекта

- `src/` — React-компоненты, TypeScript-типы, сервисы и отдельные расчётные модули.
- `frontend/` — две входные HTML-страницы Vite.
- `public/` — неизменяемые данные и ресурсы для копирования в поставку; стили интерфейса находятся в `src/`.
- `hospital-map/` — результат сборки. Для изменения интерфейса редактируйте исходники, затем выполняйте сборку.
- `scripts/` — сборка Worker, манифест, упаковка и локальный сервер.
- `data/full-project.json` — полная резервная копия для явного импорта в инструментах разработчика. Пользовательская карта автоматически её не загружает.

Исходный gzip/Base64-снимок `viewer-data.js` содержит 38 больниц, 1 942 ячейки сетки 5 км и 3 884 ответа OSRM. После заполнения пропусков автомобильные времена: 1 258 найденных маршрутов и 684 оценки; пешие: 1 733 и 209. Оценки по соседям используются для отображения и не превращаются в найденные маршруты в кэше. В просмотрщике цвета прикрепления используют фиксированные пороги 700 и 1 000, в инструментарии разработчика — терцили.

Пеший слой на обеих страницах окрашивает по времени только ячейки **до 60 минут включительно**. Более долгие пути и ячейки без времени показаны серым; исходные результаты остаются в данных, экспорте и счётчиках. В текущем снимке 102 цветные и 1 840 серых пеших ячеек. Для машины часового ограничения нет. В режиме зон прикрепления нижняя пустая легенда удалена.

Демонстрационный выпуск от 27 октября 2026 содержит прежние проверенные данные: новый автомобильный перерасчёт заблокирован отсутствием локальных графов OSRM и исходного PBF. Старый кэш не выдаётся за новый расчёт. Подробный аудит, проверки, состав изменений и оставшаяся работа: [docs/RELEASE-2026-10-27.md](docs/RELEASE-2026-10-27.md).

Подробности архитектуры, совместимости и проверки: [docs/DEVELOPER.md](docs/DEVELOPER.md). Настройка общей монохромной темы и результаты проверки интерфейса описаны в [docs/SHADCN.md](docs/SHADCN.md). Цвета тематических слоёв карты и легенды обозначают данные и сохраняются отдельно от темы оболочки.
