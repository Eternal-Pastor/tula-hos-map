# Локальный OSRM: машина и пешком

Сайт остаётся статическим; новые маршруты рассчитывают две отдельные службы OSRM на `localhost:5000` и `localhost:5001`. Готовый снимок можно просматривать без этих служб. OpenTripPlanner и общественный транспорт в эту версию не входят.

## Исходный снимок и новый автомобильный расчёт

Для нового расчёта требуются работающие OSRM, исходный PBF, подготовленные графы и их метаданные в `osrm/` и `runtime/`. Режим `Start-OSRM-WSL.ps1 -ExistingOnly` проверяет готовое окружение: он не устанавливает пакеты, не скачивает образы и не перестраивает графы.

В поставке находится сохранённый снимок: машина — 1258 найденных маршрутов, 669 `NoSegment`, 15 `NoRoute` и 684 производные оценки по соседям. Пешком — 1733 найденных, 207 `NoSegment`, 2 `NoRoute` и 209 оценок. Для получения новых результатов выполните отдельный расчёт.

Проверка исходного снимка не обнаружила перепутанных координат или несовместимых ключей: все 1942 исходные точки находятся внутри ячеек, координаты 38 больниц совпадают с исходным файлом, все 3884 ключа отвечают текущим точкам и URL. По сохранённым данным нельзя установить текущую версию графа работающего сервера. Исторические скорости согласуются с отдельными автомобильным и пешим профилями. Большое число пропусков автомобиля связано с сохранёнными ответами `NoSegment` при радиусе поиска 1000 м, а также с 15 `NoRoute`; сетевые ошибки к ним не добавляются. Время OSRM относится к точкам после привязки к дорогам, без добавления подхода к ним и без текущих пробок. Поле `profile` в URL не заменяет Lua-профиль, заданный при подготовке графа; порядок координат OSRM — долгота, широта. См. [официальную документацию OSRM API](https://project-osrm.org/docs/v5.24.0/api/).

Совпадение координат с исходным файлом не подтверждает физическую точность конечной точки. В снимке совпадают координаты головных и удалённых подразделений для Арсеньева/Одоева и Плеханова/Рассвета. Перед их исправлением подтвердите адреса и въезды, затем перестройте связанное покрытие и маршрутный кэш.

После восстановления настоящих графов выполните новый автомобильный расчёт в **отдельный** файл:

```powershell
./local-routing/Start-OSRM-WSL.ps1 -Distribution Ubuntu-24.04 -ExistingOnly
node ./local-routing/calculate-routes.cjs --input ./data/full-project.json --output ./data/full-project-auto-new.json --mode auto --fresh --concurrency 4
```

Если расчёт остановлен Ctrl+C или сетевой ошибкой, повторите ту же команду **без `--fresh`**. Сохранённые новые ответы повторно не запрашиваются. Первый запуск исключает прежние автомобильные ответы выбранного URL из входной копии и сохраняет пешие и прочие записи. Каждые 100 ответов или 10 секунд записывается контрольная точка; остановка дожидается текущей записи. Ошибка сети, HTTP 429 и некорректный JSON останавливают работу, не превращаясь в `NoRoute`. Оценки по соседям не записываются как реальные ответы.

Продолжение проверяет SHA-256 входной копии, режимы, URL, размер сетки, набор ключей, идентичность графов и SHA-256 общего расчётного движка. Эти сведения защищены контрольной суммой самой копии; отдельный `.receipt.json` содержит счётчики, признак полного завершения и те же сведения для публикации. Изменившиеся исходные данные или граф требуют другого выходного файла. `--fresh` не разрешает использовать уже существующий выходной файл. Режимы `--mode pedestrian` и `--mode both` доступны отдельно.

CLI использует автоматически собранный `engine.cjs` из тех же исходников `src/engine/`, что и приложение; поэтому он работает и в распакованной поставке, где исходников интерфейса нет. Для самого расчётного CLI нужен Node.js 22.12+, npm-пакеты устанавливать не требуется. Для обычного просмотра через `START.cmd` Node.js по-прежнему не нужен. Скрипт `build-engine.mjs` запускается только при разработке и сборке.

Прежняя схема кэша различает режим, URL и обе точки, но не содержит идентичность графа. Поэтому обычный повторный расчёт по прежнему URL может закономерно использовать старые сохранённые ответы. Свежий CLI-запуск устраняет именно эту причину подмены перерасчёта кэшем, сохраняя совместимость браузерных хранилищ.

Далее сохранён журнал подготовки OSRM от 24.10.2026 и команды обслуживания. Указания «установлен», «запущен» и результаты измерений относятся к той проверке и не подтверждают текущее состояние другого компьютера. Актуальная рабочая ветка приложения — `development`, команды сборки интерфейса описаны в [../docs/DEVELOPER.md](../docs/DEVELOPER.md). Публичные серверы, упомянутые в историческом журнале, не используются текущим интерфейсом для массового расчёта.

## Подготовка через WSL

Повторный запуск после перезагрузки — в PowerShell 7 из корня проекта:

```powershell
./local-routing/Start-OSRM-WSL.ps1
```

Сценарий установит отдельный Ubuntu-24.04, если его нет, затем Docker Engine и Osmium из репозитория Ubuntu внутри WSL. Docker Desktop для этого пути не нужен. Он обрежет дорожные данные до рамки `35.0,52.4,39.8,55.4` — Тульская область с запасом примерно 50 км — с сохранением целых дорог. Затем последовательно построит автомобильный и пеший графы двумя потоками, запустит оба контейнера и проверит маршруты и CORS с Windows. Образ OSRM фиксируется по digest в `runtime/osrm-image.txt`; готовые графы повторно не строятся, если данные, профиль и образ совпадают. Журнал подготовки: `runtime/osrm-setup.log`.

Службы слушают только localhost. Скрипт `Keep-OSRM-WSL.ps1` удерживает WSL работающим после завершения команд; его PID и время создания записываются в `runtime/`. Остановка только этих серверов и их процесса удержания: `./local-routing/Stop-OSRM-WSL.ps1`. Команда не выключает другие дистрибутивы WSL.

Для пробы сайт уже обращается к двум публичным серверам FOSSGIS. Они не требуют API-ключа, но разрешают максимум один запрос в секунду и запрещают большую нагрузку. Поэтому публичная порция ограничена одной ячейкой (два запроса), без автоматического обхода всех зон. Не используйте демонстрационный сервер для массового расчёта региона. [Условия FOSSGIS](https://routing.openstreetmap.de/about.html).

## Собственные серверы

1. Установите и запустите Docker Desktop с Linux containers. Это альтернатива Docker Engine внутри WSL. Docker Desktop может потребовать включения WSL2/виртуализации и перезагрузки; скрипт проекта это не меняет.
2. Получите OpenStreetMap PBF для Тульской области с запасом за её границами: маршруты могут выходить за регион. Источники: [Geofabrik](https://download.geofabrik.de/russia/central-fed-district.html), [экспорт Protomaps](https://app.protomaps.com/). Положите файл в `local-routing/osrm/region.osm.pbf`, создав папку `osrm`. Не используйте XML вместо PBF.
3. В PowerShell перейдите в папку `local-routing` и выполните `./Prepare-OSRM.ps1`. Скрипт копирует PBF в отдельные папки, строит автомобильный и пеший графы, затем запускает два контейнера. Подготовка требует свободной памяти, диска и времени, зависящих от размера PBF. Команды и схема MLD соответствуют [инструкции OSRM](https://github.com/Project-OSRM/osrm-backend). Образ `latest` загружается при первом запуске; для воспроизводимого исследования зафиксируйте его digest после проверки.
4. В панели сайта «Серверы OSRM» задайте:

   - машина: `http://localhost:5000/route/v1/driving`;
   - пешком: `http://localhost:5001/route/v1/foot`.

5. Нажмите «Применить серверы». Для своих серверов доступны порции до 90 запросов. Лимит Яндекса здесь не расходуется; расчёт по-прежнему запускается только кнопкой и сохраняется локально.

Контейнеры слушают только `127.0.0.1`. Перезапуск готовых графов: `docker compose up -d`. Остановка: `docker compose stop`. Журнал: `docker compose logs --tail 100`. После смены OSM-файла повторите подготовку. Результаты, уже сохранённые браузером для прежнего графа по тому же URL, остаются снимком; для нового независимого расчёта используйте новый адрес/порт и укажите его в настройках сайта.

У машины и пешего режима разные графы. Изменение слова `driving` на `foot` на одном автомобильном сервере не переключает профиль: он выбирается при подготовке данных. [Профили OSRM](https://github.com/Project-OSRM/osrm-backend/blob/master/docs/profiles.md).

Если браузер сообщает CORS, проверьте заголовки собственного OSRM. Страница обращается к нему напрямую, прокси и серверной логики в сайте нет. Запускайте сам сайт через `http://localhost:8765/`.

## Что означают времена

OSRM возвращает время по дорожному графу и скоростям подготовленного профиля, без текущих пробок. Время в пути и линия относятся к привязанным к сети точкам; радиус поиска дороги ограничен 1000 м. Время подхода от исходной точки ячейки до привязки не добавлено. В карточке показаны расстояния привязки обоих концов маршрута.

Отсутствие пути и отсутствие дороги в радиусе 1 км различаются. Ошибка сети, HTTP 429, таймаут или некорректный ответ останавливают порцию и не сохраняются как отсутствие пути. Координаты отправляются выбранному серверу только при ручном расчёте. Ключи Яндекса этому серверу не передаются.

Сетка 5 км, принадлежность больницам и цвета временных диапазонов сохранены. Кэш OSRM отделён от Яндекса и от других URL серверов; смена координат больницы или ячейки также меняет ключ. Перезагрузка использует сохранённые ответы без сетевых запросов маршрутизации. CSV и резервная копия содержат источник, сервис и расстояния привязки.


## Массовый расчёт из резервной копии

Нужен Node.js 22.12+; устанавливать npm-пакеты не требуется. Из корня проекта:

```powershell
node ./local-routing/calculate-routes.cjs --input ./backups/hospital-project-full-coverage-2026-10-24.json --output ./backups/hospital-project-osrm-2026-10-24.json --step 5000 --concurrency 4
```

Расчёт разрешён только для loopback-серверов, публичные endpoints отклоняются. Входная копия не изменяется. Результат — обычная копия проекта версии 2 с SHA-256, исходными адресами, обоими снимками зон, прежними маршрутами и новыми локальными ответами. Для продолжения используйте те же входной и выходной файлы: уже сохранённые ответы с тем же графом не запрашиваются. При смене графа продолжение в старый файл запрещено. Контрольные точки сохраняются каждые 100 ответов или 10 секунд; ошибки сети останавливают расчёт с сохранением полученного. NoSegment и NoRoute сохраняются отдельно, время для них null. Искусственная задержка публичных сервисов сохраняется для внешних endpoints; loopback-запросы её не используют.
